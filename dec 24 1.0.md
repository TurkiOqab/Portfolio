## Key Decisions

### Security Architecture
- **Decision**: Add rehype-sanitize to MarkdownRenderer instead of removing rehype-raw
- **Rationale**: Preserves ability to render HTML in markdown (needed for rich content) while preventing XSS attacks through sanitization
- **Implementation**: rehype-sanitize configured as final plugin in rehype chain to clean any dangerous HTML

### Input Validation Strategy
- **Decision**: Implement strict validation for track-view API (UUID format, visitor ID pattern)
- **Rationale**: Prevents malformed data from entering analytics database, reduces attack surface
- **Implementation**: Added regex validation with specific error messages for debugging

### Performance Pattern
- **Decision**: Memoize Supabase clients rather than creating singletons
- **Rationale**: Respects React component lifecycle while preventing unnecessary object creation
- **Implementation**: Used useMemo with empty dependency array in Navbar and LikeButton

### Code Organization
- **Decision**: Extract consent utilities to shared `/app/lib/consent.ts`
- **Rationale**: Eliminates duplicate implementations in ViewTracker and LikeButton, creates single source of truth
- **Implementation**: Exported hasConsent() and getVisitorId() functions

### State Management Pattern
- **Decision**: Use refs for typewriter/rotation effects instead of cascading setState
- **Rationale**: Prevents excessive re-renders, improves performance, avoids React warning about setState in render
- **Implementation**: Hero.tsx and RotatingSlogan.tsx now use useRef for internal state tracking

## Technical Details

## Context for Future Sessions

### Code Architecture Decisions
- **Consent System**: All analytics features (views, likes) respect cookie consent via localStorage
- **Visitor ID Pattern**: Format is `visitor_[timestamp]_[random]` - do not change without updating API validation
- **Markdown Security**: Always use both rehype-raw AND rehype-sanitize together - removing either breaks functionality or security

### Important Gotchas
1. **Supabase Clients**: Use `useMemo` for client memoization, not module-level singletons (breaks with Next.js SSR)
2. **React Hooks**: Always declare hooks before any conditional returns or loops
3. **Image Components**: Use Next.js `<Image>` for all user-uploaded or dynamic images for automatic optimization
4. **setState in Effects**: Prefer initializing state with computed values over setting state in useEffect

- `/app/api/track-view/route.ts` - Analytics endpoint with strict validation
